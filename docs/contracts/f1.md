# Kontrakt etapu F1: wiedza (MP1)

Ten dokument zamienia F1 z [07-roadmap.md](../07-roadmap.md) na zadania z kontraktami. Wymagania: FR-1.1–FR-1.5, FR-6.3, FR-6.4 ([02-requirements.md](../02-requirements.md)). Decyzje, które zmieniają wcześniejsze ustalenia: [ADR-0007](../adr/0007-knowledge-index-f1.md). Stan wyjściowy: [f0.md](f0.md) (F0 zmergowane).

**F1 jest gotowe, gdy:**
1. `kovalo eval e1` daje dla korpusu 18 dokumentów / 8762 tokeny / 47 chunków (najdłuższy ≤ 800 znaków), a wiersz „referencja kursu” (tryb `openai_cache`) odtwarza przebieg wzorcowy MP1 co do znaku: hit@1/hit@3 0,9/0,9, top-3 dla Q01–Q10, $17,78 / $69,86 (x3,9).
2. Raport E1 (`reports/mp1/<data>-e1.md`) porównuje co najmniej 4 modele fastembed, a ADR-0003 ma status „przyjęty” z wybranym modelem i wynikami (§11).
3. `make ingest` dwa razy z rzędu daje w Postgresie dokładnie 47 wierszy w `kovalo_mp1`; drugi przebieg nie liczy żadnego embeddingu (wszystkie z cache).
4. `uv run pytest` (unit + architektura) przechodzi w CI; `uv run pytest -m integration` przechodzi przy działającym compose.

### 2.1 Polecenia

| Polecenie | Gdzie | Co robi |
|---|---|---|
| `kovalo ingest` | `make ingest` = `docker compose run --rm api kovalo ingest`; lokalnie `make ingest-local` | korpus → chunki MP1 → embeddingi (cache) → podmiana tabeli `kovalo_mp1` |
| `kovalo eval e1 [opcje]` | `make eval STAGE=e1 ARGS="..."`; lokalnie `make eval-local STAGE=e1 ARGS="..."` | ewaluacja E1, raporty w `reports/mp1/` |

### 2.2 Gdzie co biegnie

- `ingest` i `eval e1` z modelem z configu: w compose (model wbudowany w obraz) albo lokalnie.
- `eval e1 --candidates`: lokalnie (`uv run`), bo pobiera wszystkich kandydatów do `.cache/fastembed`. W compose też zadziała, jeśli kontener ma sieć i `local_files_only` jest wyłączone (`KOVALO_EMBEDDINGS__LOCAL__LOCAL_FILES_ONLY=false`), ale modele przepadną po `--rm`.

### 2.3 Zasady zależności (dopisać do `tests/architecture/test_dependencies.py`)

Obowiązują wszystkie zasady z [f0.md §2.3](f0.md). Nowe:
- `fastembed` importuje tylko `kovalo/knowledge/embeddings.py` (i to leniwie, wewnątrz `FastEmbedEmbeddings.__init__`, żeby import `kovalo.knowledge` nie ładował onnxruntime).
- `langchain_postgres` importuje tylko `kovalo/knowledge/pgvector.py`.
- `tiktoken` importuje tylko `kovalo/cost/tokens.py`.
- `knowledge/` i `cost/` nie importują `kovalo.llm`, `kovalo.eval`, `kovalo.cli`. Model embeddingów dostają przez parametr; składa je `cli.py` albo `eval/` przez `kovalo.llm.get_embeddings`.
- `cost/` nadal bez `langchain*` i `langgraph*` (może importować `kovalo.config` i `tiktoken`).
- `eval/` może importować `kovalo.knowledge`, `kovalo.cost`, `kovalo.llm`; nie importuje `kovalo.cli`, `kovalo.api`, `kovalo.ui`.
- `ui/` nie importuje `kovalo.knowledge`, `kovalo.cost`, `kovalo.eval` (już częściowo w F0).
- Literały nazw modeli embeddingów (`intfloat/`, `jinaai/`, `sentence-transformers/`) tylko w `config.yaml` i `docker/Dockerfile`, nigdy w `src/` (rozszerzenie `test_no_model_names_in_src`).

    n_documents: int
    total_tokens: int
    tokens_by_doc_type: dict[str, int]
    largest_document: str                # doc_id; remis → alfabetycznie pierwszy

- Dokument = każdy plik `*.md` w `corpus_dir` (nie rekurencyjnie); `catalog.csv` nie jest dokumentem.
- `page_content` = `path.read_text(encoding="utf-8")` bez zmian.
- `metadata` = dokładnie `required_metadata` z wiersza katalogu + `"source"` (sama nazwa pliku). Kolumna `file` nie trafia do metadanych.
- Wynik posortowany po `doc_id`.
- `CorpusError`: plik `.md` bez wiersza w katalogu; pusty napis w wymaganym polu; wiersz katalogu wskazujący nieistniejący plik (FR-1.1, nasze rozszerzenie); powtórzony `doc_id`; brak katalogu (komunikat ze ścieżką; nie `FileNotFoundError`).
- `tokens_per_word_by_language`: tekst wszystkich dokumentów języka połączony `"\n"`, tokeny / `len(text.split())` (jak `run_pipeline.py`).

**Reguła wyboru modelu (`recommend_model`, deterministyczna):**
1. Kandydaci: wiersze `fastembed` z `meets_target`; gdy żaden nie spełnia celu, wszystkie wiersze `fastembed`.
2. `best` = maksimum po (`mp1.hits_at_3 + mp2.hits_at_3`, `mp1.hits_at_1 + mp2.hits_at_1`, `mp1.mrr + mp2.mrr`).
3. Spośród kandydatów, którzy mają łącznie co najwyżej o 1 trafienie mniej niż `best` zarówno w hit@3, jak i w hit@1, wybieramy najmniejszy `size_gb` (remis → kolejność z punktu 2). Powód: model ładują dwa kontenery (`api` od F1, `mcp-server` od F5), więc 2 GB różnicy to realny koszt RAM i rozmiaru obrazu.
