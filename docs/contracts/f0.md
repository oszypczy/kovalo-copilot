### 2.1 Punkty wejścia (`[project.scripts]`)

```toml
[project.scripts]
kovalo     = "kovalo.cli:entrypoint"          # kovalo first-call (F0), ingest (F1), eval (F1+)
kovalo-api = "kovalo.api.main:run"            # uvicorn, factory create_app, 0.0.0.0:services.api_port
kovalo-ui  = "kovalo.ui.server:run"           # uvicorn kovalo.ui.server:app, 0.0.0.0:services.ui_port
kovalo-mcp = "kovalo.mcp_server.server:entrypoint"  # --transport stdio|streamable-http [--host] [--port]
```

`run()` / `entrypoint()` nie przyjmują argumentów i nie zwracają wartości (`entrypoint` kończy proces przez `sys.exit(main())`). Testy wywołują `main(argv: Sequence[str] | None = None) -> int`.

### 2.3 Zasady zależności (sprawdzane testem `tests/architecture/test_dependencies.py`)

Uzupełniają [03-architecture.md §2](../03-architecture.md):
- `config.py` i `health.py` nie importują LangChaina ani LangGraph. Importują je wszyscy, więc muszą być lekkie.
- Tylko `llm.py` importuje `langchain_google_genai`, `langchain_openai` i `init_chat_model`. Reszta kodu dostaje model z `kovalo.llm` albo przez parametr.
- `policy/`, `company/`, `cost/` nie importują `langchain*`, `langgraph*`, `kovalo.llm`.
- `ui/` nie importuje `kovalo.llm`, `kovalo.workflow`, `kovalo.agents`, `kovalo.tools`, `kovalo.knowledge`, `kovalo.rag` (rozmawia z `api` przez HTTP).
- `workflow/` nie importuje `mcp`, `kovalo.mcp_client`, `kovalo.mcp_server`.
- Literały nazw modeli (`gemini-`, `gpt-`) występują tylko w `config.yaml`, nigdy w `src/`.

### 4.3 `kovalo.config`: kontrakt

```python
class ConfigError(RuntimeError): ...            # zła albo brakująca wartość w config.yaml/env
class MissingConfigError(ConfigError): ...      # brak wymaganej zmiennej środowiskowej (np. klucza API)

ModelProvider = Literal["google_genai", "openai"]
ModelPurpose = Literal["default", "understand", "answer", "judge", "agent"]

# Modele sekcji: pydantic.BaseModel, model_config = ConfigDict(extra="forbid", frozen=True)
class PathsConfig       # wszystkie klucze paths.* kursu jako Path, po walidacji absolutne (względem katalogu config.yaml)
class CorpusConfig      # required_metadata: list[str]
class TokenizerConfig   # encoding: str
class ChunkingConfig    # chunk_size: int; chunk_overlap: int; separators: list[str]
class LocalEmbeddingsConfig  # model: str; dimensions: int; models_dir: Path; cache_dir: Path
class EmbeddingsConfig  # model: str; dimensions: int; batch_size: int; provider: Literal["fastembed","openai_cache"]; local: LocalEmbeddingsConfig
class RetrievalConfig   # top_k: int
class ReferenceLlmConfig  # provider: str; model: str
class RateLimitConfig   # requests_per_second: float (>0); check_every_n_seconds: float = 0.1; max_bucket_size: float = 1
class ModelSpec         # provider: ModelProvider; model: str; rate_limit: RateLimitConfig | None = None (None → jak główny)
class PurposeOverride   # model: str | None = None; temperature: float | None = None
class LlmConfig         # provider, model, temperature: float | None, max_retries: int = 2, timeout_s: float = 60,
                        # params: dict[str, Any] = {}, rate_limit: RateLimitConfig, fallbacks: list[ModelSpec] = [],
                        # purposes: dict[ModelPurpose, PurposeOverride] = {}
class TokenPrice        # input: float; output: float
class CostScenario      # questions_per_day: int; working_days_per_month: int; output_tokens_per_answer: int
class CostConfig        # reference_model: str; prices_per_1m_tokens: dict[str, TokenPrice]; scenario: CostScenario
class PolicyBand        # up_to: int; roles: list[str]
class PolicyException   # cap: int; roles: list[str]
class PolicyConfig      # version: str; bands: list[PolicyBand]; exceptions: dict[str, PolicyException]; margin_floor: int; floor_role: str
class AgentConfig       # max_steps: int; timeout_s: int
class McpConfig         # startup_timeout_s: int; call_timeout_s: int; cleanup_timeout_s: int
class PromptsConfig     # system, answer_system, understand_system, agent_system, assistant_understand_system: str
class DbConfig          # host: str; port: int; connect_timeout_s: float; pool_min_size: int; pool_max_size: int;
                        # vector_collection: str; vector_collection_mp1: str
class ServicesConfig    # api_port, ui_port, mcp_port: int; api_url: str; mcp_url: str; health_timeout_s: float

class Settings(BaseSettings):
    # z config.yaml (sekcje PINNED i kursu bez wartości domyślnych: muszą być w pliku)
    paths: PathsConfig; corpus: CorpusConfig; tokenizer: TokenizerConfig; chunking: ChunkingConfig
    embeddings: EmbeddingsConfig; retrieval: RetrievalConfig; reference_llm: ReferenceLlmConfig
    llm: LlmConfig; cost: CostConfig; policy: PolicyConfig; agent: AgentConfig; mcp: McpConfig
    prompts: PromptsConfig; db: DbConfig = DbConfig(); services: ServicesConfig = ServicesConfig()
    root: Path                                  # katalog config.yaml (ustawiany przy ładowaniu)

    # sekrety i zmienne z env / .env (aliasy bez prefiksu)
    google_api_key: SecretStr | None            # GOOGLE_API_KEY, zapasowo GEMINI_API_KEY
    openai_api_key: SecretStr | None            # OPENAI_API_KEY
    langsmith_tracing: bool = False             # LANGSMITH_TRACING
    langsmith_api_key: SecretStr | None         # LANGSMITH_API_KEY
    langsmith_project: str = "kovalo-copilot"   # LANGSMITH_PROJECT
    postgres_user: str = "kovalo"               # POSTGRES_USER
    postgres_password: SecretStr = SecretStr("kovalo")  # POSTGRES_PASSWORD
    postgres_db: str = "kovalo"                 # POSTGRES_DB

    def api_key_for(self, provider: ModelProvider) -> SecretStr | None: ...
    def postgres_dsn(self) -> str: ...          # "postgresql://user:pass@host:port/db" (psycopg, PostgresSaver)
    def sqlalchemy_url(self) -> str: ...        # "postgresql+psycopg://…" (langchain-postgres)

def api_key_env_name(provider: ModelProvider) -> str: ...   # "GOOGLE_API_KEY" | "OPENAI_API_KEY" (komunikaty llm i health)
def default_config_file() -> Path: ...           # kolejność szukania config.yaml, patrz niżej
def load_settings(config_file: Path | None = None, **overrides: Any) -> Settings: ...   # bez cache, dla testów i CLI
@functools.cache
def get_settings() -> Settings: ...             # jedna instancja na proces; testy: get_settings.cache_clear()
```

Źródła i priorytet (od najwyższego): argumenty `load_settings(**overrides)` → zmienne środowiskowe → `.env` (katalog bieżący) → `config.yaml` → wartości domyślne. Ścieżka pliku: argument `config_file`, potem `KOVALO_CONFIG_FILE`, potem `<katalog główny repo>/config.yaml` (gdy pakiet jest zainstalowany w trybie edytowalnym z repo), na końcu `<katalog bieżący>/config.yaml`. W obrazie pakiet jest zainstalowany nieedytowalnie, więc działa ostatni krok (`WORKDIR /app` → `/app/config.yaml`). Ścieżki `paths.*` oraz `embeddings.local.models_dir` i `embeddings.local.cache_dir` są po walidacji absolutne względem katalogu `config.yaml`. Implementacja: `settings_customise_sources` z `YamlConfigSettingsSource`.

Nadpisania z env: prefiks `KOVALO_`, separator zagnieżdżenia `__` (np. `KOVALO_LLM__MODEL`, `KOVALO_DB__HOST`). Sekrety mają aliasy bez prefiksu (`validation_alias`), dokładnie takie jak w `.env.example`.

Błędy i przypadki brzegowe:
- brak pliku, YAML, który nie jest mapowaniem, nieznany klucz (`extra="forbid"`), zły typ → `ConfigError` z nazwą klucza i ścieżką pliku (opakowany `ValidationError`);
- brak `GOOGLE_API_KEY` **nie** jest błędem ładowania (`google_api_key=None`), bo `api`, `ui` i `mcp-server` muszą wstać bez klucza. Błąd zgłasza dopiero `kovalo.llm` (sekcja 5.3);
- pusty string w env (`GOOGLE_API_KEY=` z `.env.example`) traktujemy jak brak (`None`);
- `repr(settings)` i logi nigdy nie pokazują sekretów (`SecretStr`);
- `config.py` nie eksportuje zmiennych do `os.environ`. LangSmith czyta swoje zmienne sam, więc lokalnie uruchamiamy przez `uv run --env-file .env`, a w compose przez `env_file: .env`.

| Zmienna | Skąd | Uwagi |
|---|---|---|
| `GOOGLE_API_KEY` | `.env` | wymagana tylko do wywołań LLM-a |

Szkic na kolejne etapy (nie implementujemy w F0, tylko rezerwujemy nazwy):
- `get_structured_model(schema: type[BaseModel], purpose: ModelPurpose, *, include_raw: bool = True) -> Runnable` (F2/F3): `with_structured_output` nakładane na model główny i na każdy fallback osobno, potem `with_model_fallbacks`. Kolejność jest ważna: fallback ma dostać ten sam schemat.
- `get_fallback_middleware(purpose) -> ModelFallbackMiddleware` (F4) dla `create_agent`.
- `get_embeddings() -> Embeddings` (F1): fabryka fastembed z `CacheBackedEmbeddings`.

### 5.2 Budowa modelu

`get_chat_model` woła:

```python
init_chat_model(
    spec.model,                                  # z llm.model albo llm.purposes[purpose].model
    model_provider=spec.provider,
    api_key=settings.api_key_for(spec.provider).get_secret_value(),
    max_retries=llm.max_retries,
    timeout=llm.timeout_s,
    rate_limiter=_limiter_for(spec),             # patrz niżej
    **({"temperature": t} if t is not None else {}),   # null → nie przekazujemy
    **llm.params,                                # tylko dla provider == google_genai
)
```

- **Rate limiter:** `langchain_core.rate_limiters.InMemoryRateLimiter(requests_per_second=…, check_every_n_seconds=…, max_bucket_size=…)` z `llm.rate_limit` (dla fallbacku z `ModelSpec.rate_limit` albo z głównego). Rejestr na poziomie modułu: **jeden limiter na `(provider, model)` w procesie**, współdzielony przez wszystkie wywołania `get_chat_model` i wszystkie cele. Bez tego każdy węzeł miałby własny limiter i razem przekroczyłyby RPM. Limiter liczy tylko żądania, nie tokeny. Działa w obrębie jednego procesu: `api` i jednorazowy `kovalo eval` mają osobne budżety.
- **`params`** (np. `thinking_level`) idą tylko do modeli `google_genai`. Model `openai` ich nie dostaje.
- **Cel (`purpose`)** wybiera tylko nadpisanie z `llm.purposes` (model, temperatura). Nie opakowujemy modelu w `with_config`, bo zwracany typ musi zostać `BaseChatModel`. Tagi przebiegu (LangSmith) dodaje wywołujący przez `config={"tags": [...]}`.

### 5.3 Błędy

| Sytuacja | Zachowanie |
|---|---|
| brak klucza dla dostawcy (główny albo fallback) | `MissingConfigError` przed jakimkolwiek wywołaniem sieci. Komunikat: `Brak GOOGLE_API_KEY. Ustaw klucz w .env (darmowy: https://aistudio.google.com/apikey).` |
| `provider: openai` bez zainstalowanego extra | `ConfigError("Dostawca openai wymaga: uv sync --extra openai")` |
| 429 / 5xx / 404 / timeout / zerwane połączenie w modelu głównym | `with_fallbacks` przechodzi do następnego modelu z `llm.fallbacks` |
| 400, 401, 403, przepełnienie kontekstu, `OutputParserException`, `ValidationError`, `ValueError` | **bez fallbacku**, wyjątek idzie wyżej (ten sam klucz albo to samo żądanie zawiedzie też w fallbacku) |
| wszystkie modele zawiodły | wyjątek z ostatniego modelu (zachowanie `RunnableWithFallbacks`) |

Uwagi z kodu `langchain-google-genai` 4.4: błędy 4xx mają typy `GoogleRateLimitError`, `GoogleModelNotFoundError` itd., które dziedziczą po `ChatGoogleGenerativeAIError` i po klasach `langchain_core.exceptions.Model*Error`, a 5xx to `GoogleAPIError(ServerError, ModelAPIError)`. Dzięki temu lista `FALLBACK_EXCEPTIONS` nie zależy od dostawcy. `max_retries=1` wyłącza ponowienia (`0` oznacza domyślne ponowienia SDK).

### 5.4 Wynik wywołania

`AIMessage` z Gemini 3 może mieć `content` w postaci listy bloków. Tekst bierzemy zawsze z `message.text` (w langchain-core 1.x to właściwość, nie metoda), tokeny z `message.usage_metadata`, a faktycznie użyty model z `message.response_metadata["model_name"]`.

### 5.5 Atrapy w testach

- Testy kodu korzystającego z modelu dostają model przez parametr (fabryki grafu, węzły) albo przez `override_chat_model(...)`.
- Atrapy: `langchain_core.language_models.fake_chat_models.GenericFakeChatModel(messages=iter([AIMessage(...)]))`; do testów fallbacku: fixture `failing_chat_model(exc)`, czyli podklasa `BaseChatModel`, której `_generate` rzuca podany wyjątek.
- Testy samego `llm.py` budują prawdziwy `ChatGoogleGenerativeAI` z kluczem `"test-key"`. Konstruktor nie łączy się z siecią, więc to bezpieczne bez markera `live`.

### 6.2 Format odpowiedzi (`kovalo.health`)

```python
CheckState = Literal["ok", "error", "skipped"]
ServiceState = Literal["ok", "degraded", "error"]
ServiceName = Literal["api", "ui", "mcp-server"]

class CheckResult(BaseModel):
    status: CheckState
    critical: bool = False
    detail: str | None = None        # po polsku, bez sekretów i DSN z hasłem
    latency_ms: float | None = None

class HealthReport(BaseModel):
    status: ServiceState
    service: ServiceName
    version: str                     # kovalo.__version__
    checks: dict[str, CheckResult] = {}

CheckFn = Callable[[], Awaitable[CheckResult]]

async def check_postgres(settings: Settings) -> CheckResult      # psycopg AsyncConnection, SELECT 1, connect_timeout
async def check_http(url: str, *, timeout_s: float, critical: bool = False) -> CheckResult   # GET; 2xx → ok
def check_llm_configured(settings: Settings) -> CheckResult      # tylko obecność klucza; ZERO wywołań LLM-a
async def build_report(service: ServiceName, checks: Mapping[str, CheckFn], *,
                       timeout_s: float | None = None,      # None → get_settings().services.health_timeout_s
                       critical: Collection[str] = ()) -> HealthReport   # nazwy krytyczne także przy timeoucie/wyjątku
def http_status(report: HealthReport) -> int                     # error → 503, w pozostałych → 200
```

Agregacja: którykolwiek `critical` z `error` → `error`; którykolwiek niekrytyczny z `error` → `degraded`; inaczej `ok`. Każde sprawdzenie ma limit `services.health_timeout_s` (usługi przekazują go jawnie przez `timeout_s`, domyślne `None` to tylko wygoda dla testów); przekroczenie daje `error` z `detail="przekroczono limit czasu"`. Wyjątek w sprawdzeniu też daje `error`, a nie 500.

| Usługa | Sprawdzenia (krytyczne pogrubione) |
|---|---|
| `api` | **`postgres`**, `mcp` (`GET {mcp_url bez /mcp}/health`), `llm` (klucz skonfigurowany) |
| `ui` | `api` (`GET {api_url}/health`) |
| `mcp-server` | brak w F0 (od F5: indeks w pgvector) |

`degraded` zwraca 200, więc healthcheck compose (`curl -fsS …/health` albo odpowiednik w Pythonie) uznaje usługę za zdrową, nawet bez klucza Gemini. Przykład:

```json
{"status": "degraded", "service": "api", "version": "0.1.0",
 "checks": {"postgres": {"status": "ok", "critical": true, "detail": null, "latency_ms": 3.1},
            "mcp": {"status": "ok", "critical": false, "detail": null, "latency_ms": 5.0},
            "llm": {"status": "error", "critical": false, "detail": "brak GOOGLE_API_KEY", "latency_ms": null}}}
```

Sprawdzenia trafiają do aplikacji przez zależność `kovalo.api.deps.get_health_checks`, więc testy podmieniają je przez `app.dependency_overrides`.

| Rozszerzenie | Decyzja | Uzasadnienie |

### 9.3 Niezgodność do poprawy (A4, T2)

`config.py:233-242`: `Settings` ma `extra="forbid"`, a źródło `.env` (`DotEnvSettingsSource`) przekazuje do walidacji **każdą** zmienną z pliku `.env`, która nie pasuje do pola. Sprawdzone: `.env` z `API_PORT=9090` albo `KOVALO_CONFIG_FILE=...` (oba opisane w §4.4 i w `.env.example` jako dopuszczalne) daje `ConfigError: Extra inputs are not permitted` przy lokalnym uruchomieniu (`make first-call-local`, testy z katalogu repo). W compose problem nie występuje, bo `env_file` trafia do zmiennych środowiskowych, a źródło env pomija nieznane klucze.

Kontrakt poprawki:
- `Settings.model_config`: `extra="ignore"` na poziomie głównym; sekcje (`_Section`) zostają z `extra="forbid"`.
- Ochronę przed literówką w głównych kluczach `config.yaml` przejmuje `_check_yaml_file`: klucze główne spoza `Settings.model_fields` → `ConfigError` z nazwą klucza i ścieżką pliku.
- Testy (T2, `tests/unit/test_config.py`): `test_dotenv_unknown_keys_ignored` (`.env` w `tmp_path` jako katalogu bieżącym z `API_PORT` i `KOVALO_CONFIG_FILE` → ładuje się bez błędu), `test_unknown_top_level_yaml_key_rejected` (`llmm:` w YAML → `ConfigError` z `llmm`). Istniejący `test_unknown_key_rejected` (klucz w sekcji `llm`) musi zostać zielony.

### 9.4 Rozwiązane: czas odpowiedzi modelu głównego

`make first-call` w compose: `gemini-3.8-flash` nie odpowiedział w limicie `llm.timeout_s: 60` (z `max_retries: 2` SDK próbuje ponownie, zanim `ModelTimeoutError` uruchomi fallback), a odpowiedź dał `gemini-3.5-flash-lite` po 131 s łącznie. Wartości `llm.timeout_s`, `llm.max_retries` (i ewentualnie `llm.params.thinking_level`) czekają na decyzję właściciela projektu; zmiana wymaga aktualizacji ADR-0006. Do czasu decyzji F0 uznajemy za spełnione (odpowiedź Gemini przyszła), ale przed F2 (sędzia LLM, ewaluacje) czas pojedynczego wywołania musi spaść, bo 131 s na wywołanie blokuje E2.

**Decyzja (2026-11-02):** `llm.max_retries: 1` (bez ponowień w SDK, po timeoucie od razu fallback), `timeout_s: 60` bez zmian. Zapisane w ADR-0006. Czas odpowiedzi Flasha mierzymy ponownie w F1.

### 9.5 Ograniczenie zależności

`[tool.uv] constraint-dependencies = ["cryptography>=46,<47"]` (zależność pośrednia: `google-auth`, `pyjwt[crypto]` przez `chainlit` i `mcp`). Nie wymaga ADR-u: nie zmienia technologii, kontraktu, wartości PINNED ani promptu. Opis i warunek usunięcia: [04-tech-stack.md](../04-tech-stack.md#ograniczenia-zależności).
