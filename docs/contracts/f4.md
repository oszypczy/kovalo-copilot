Dla zgodności z F5: `reference/course/mini_project_5/src/step3_answer_with_tools.py`, `helpers/assistant.py`.

**F4 jest gotowe, gdy:**
1. Narzędzia na prawdziwych danych firmy dają wzorzec kursu: kara P1 = **729 600**, P2 = **362 400**, P3 = **0** groszy (`tests/unit/company/`, port `test_provided_company_data.py`), a `check_termination_condition("Mleczna Dolina", "2026-09")` zwraca `condition_met = False` z lipcem 94,6% jako miesiącem, który nie jest poniżej progu 94%.

4. W UI (`make up`, http://localhost:8000) pytanie P1 i T1 pokazują kroki agenta na bieżąco (`cl.Step` na każde wywołanie narzędzia, w T1 zagnieżdżony odczyt `get_supplier_otif` pod `check_termination_condition`), odpowiedź ze źródłami i zwiniętą „Ścieżkę dowodową”; `GET /threads/{id}/trace` zwraca ten trace także po `docker compose restart api`. Scenariusz D2 z F3 działa bez zmian.
5. `uv run pytest` (unit + architektura) zielone w CI; `-m integration` (agent w grafie na `PostgresSaver`, SSE i `/trace` w compose bez LLM-a) zielone; `-m live tests/live/test_e4_live.py` to najwyżej 4 wywołania Gemini.

### 2.1 Polecenia

| Polecenie | Gdzie | Co robi |
|---|---|---|
| `kovalo eval e4 [opcje]` | `make eval STAGE=e4 ARGS="..."`; lokalnie `make eval-local STAGE=e4 ARGS="..."` | E4: przeliczenie przebiegów kursu i odtworzenie (zawsze), przebieg na żywo (`--live`), raporty w `reports/mp4/` (§11.6) |

### 2.2 Gdzie co biegnie

- Testy jednostkowe, `eval e4` bez `--live`, `eval e4 --live --cache-only`: bez sieci i bez klucza. Wyszukiwanie w E4: magazyn w pamięci z chunków `ctx` i modelem fastembed z configu (`knowledge.build_memory_retriever`, jak E3 na żywo); w testach `DeterministicFakeEmbedding`.
- `eval e4 --live`: lokalnie albo w compose; wymaga `GOOGLE_API_KEY`; cache LLM-a w `paths.llm_cache_dir`.
- `api` w compose: agent z wyszukiwaniem w `kovalo_ctx` (pgvector), dane z `/app/data/company`, trace w checkpointach Postgresa, bez cache LLM-a.

```python
    embedding_model: str | None
    reference: dict                      # course_e4(...)
    course: E4Run; course_supervisor: E4Run; replay: E4Run; live: E4Run | None
    llm_calls_planned: dict              # plan_llm_calls
    max_calls: int | None
    stopped_by_max_calls: bool = False
    live_cost_cents: dict | None = None  # {'ours', 'reference'} jak E3
    our_cost_model: str; our_prices_checked_on: date; reference_cost_model: str

def plan_llm_calls(questions: Sequence[AgentGold]) -> dict[str, int]:
    """{'estimate': szacunek tur modelu (penalty 3, termination 3, pozostałe 2; pełny zestaw 22),
    'upper_bound': len × ceil(agent.max_steps / 2) (pełny zestaw 9 × 12 = 108)}."""

def run_e4(settings: Settings, *, live: bool = False, ids: Sequence[str] | None = None,
           cache: BaseCache | None = None, offline: bool = False, max_calls: int | None = 20,
           backend: Literal["memory", "pgvector"] = "memory", variant: Literal["course", "ours"] | None = None,
           model: BaseChatModel | None = None) -> E4Report:
    """Zawsze: course + course_supervisor (przeliczenie), replay (§11.3). live=True: AgentRunner z
    build_agent_runner(settings, retriever=…, cache, offline, variant, extra_middleware=[CallMeter(cache, max_calls)])
    albo podany model (testy). Wyszukiwanie (replay i live, backend memory): build_memory_retriever(settings,
    llm.get_embeddings(settings=settings)), więc testy podmieniają embeddingi przez override_embeddings (P7).
    Pytania po kolei; CallBudgetExhausted w pytaniu → to pytanie i wszystkie następne
    dostają Trace(status='error', error='pominięte: wyczerpany limit --max-calls') i stopped_by_max_calls=True.
    ids: podzbiór (nieznane → ConfigError). Każde pytanie na żywo z błędem (nie licząc pominiętych) → E4AllErrorsError."""
```

Raporty w `--out` (domyślnie `reports/mp4`): `<data>-e4.md`, `<data>-e4.json` (`E4Report`), `agent_run.replay.json` i `agent_run.live.json` (format `save_traces` kursu, z `score`, więc `kovalo show-trace` i `show_trace.py` kursu je czytają). Sekcje Markdown, w tej kolejności:

## 12. Budżet wywołań LLM-a (darmowy tier)

Model główny `gemini-3.5-flash-lite` (ok. 20 zapytań dziennie na model, reset o północy czasu pacyficznego), fallback `gemini-3.6-flash` (20/dzień). Jedna tura modelu agenta = jedno wywołanie; narzędzia nie wywołują LLM-a (wyszukiwanie: embeddingi lokalne). Kurs: 25 tur modelu na 9 pytań (gpt-5.4-mini).

| Uruchomienie | Wywołania (szacunek / górna granica) |
|---|---|
| `uv run pytest` (unit, architektura), `-m integration` | **0** |
| `kovalo eval e4` (przeliczenie + odtworzenie) | **0** |
| `kovalo eval e4 --live` (9 pytań) | **≈ 22–25** / 108; z `--max-calls 20` najwyżej 20 na uruchomienie |
| dzień 1: `--live --ids P1,P2,P3,T1,A1` | ≈ 13 |
| dzień 2: `--live --ids D1,S1,N1,B1`, potem `--live` (całość z cache) | ≈ 8 + 0 |
| powtórka `--live --cache-only` | **0** (bez klucza) |
| `pytest -m live tests/live/test_e4_live.py` (P1, `max_calls=4`, bez cache) | ≤ 4 |
| A8 lokalnie: P1 w UI (`understand` + agent) | ≈ 4 |
| D2 w compose: P1 przez `curl -N` (≈ 4), T1 w UI (≈ 4), D2 z F3 w UI (2) | ≈ 10 |
| **Zamknięcie F4** (A10 + test na żywo + A8 + D2) | **≈ 40** w 2–3 dniach |
| **Faktycznie (2026-11-03):** E4 na żywo 24 tury modelu (wszystkie Flash-Lite, 8 sieciowo w drugim przebiegu, 16 z cache, 0 błędów), test na żywo ≤ 4, D2 w compose z agentem 9, UI (A8, P1 i D2) ok. 10 | **≈ 47** |
| opcjonalnie: U5 (`agent_system_v2`, `--ids T1` przed i po) | + ≈ 3–6 |
| opcjonalnie: U6 wariant B (przebieg `--tools course`) | + ≈ 22 (osobny dzień) |

- Cache zapisuje udane odpowiedzi; przerwany przebieg (limit dzienny, `--max-calls`, 429) powtarza tylko brakujące wywołania. Klucz cache zależy od historii wiadomości agenta, a ta jest deterministyczna, dopóki wcześniejsze tury przychodzą z cache, a narzędzia zwracają to samo (dane i wyszukiwanie są deterministyczne).
- Czas: limiter 0,25 zapytania/s → ok. 90–100 s na 22 wywołania; limit 180 s jest na pytanie.
- Fallback w środku pętli agenta przełącza model między turami (mieszanie modeli widoczne w `answered_by`, U10).
