# Kontrakt etapu F5: MCP i końcowy asystent (MP5)

Ten dokument rozpisuje F5 z [07-roadmap.md](../07-roadmap.md) na zadania z kontraktami. Wymagania: FR-5.1–FR-5.5, FR-6.2 (część: scenariusz C1–C5 w UI), FR-6.4 (raport E5), NFR-5 (audytowalność wywołań MCP), NFR-7 (żadnych kluczy w argumentach i wynikach narzędzi) ([02-requirements.md](../02-requirements.md)). Decyzje: [ADR-0005](../adr/0005-mcp-streamable-http.md) (oba transporty, własny klient na MCP SDK), [ADR-0011](../adr/0011-agent-tools-f4.md) pkt 2 i 6 (specyfikacje narzędzi wspólne z MCP, agent w węźle `answer_documents`), nowe: [ADR-0013](../adr/0013-mcp-server-client-f5.md) (serwer i klient MCP, źródło narzędzi agenta, pochodzenie wywołania w artefakcie, kontekst agenta) i [ADR-0014](../adr/0014-assistant-eval-e5.md) (E5, E4 przez MCP, liczenie nieudanych prób). Stan wyjściowy: [f4.md](f4.md) (F4 zmergowane, §18.6); uwagi R1-2, R1-6, R1-10 i B1 z [f4.md §18.5–18.6](f4.md) są tu zadaniami A0, D1 i decyzją U10.

Specyfikacja kursu: [mp5_README.md](../course/mp5_README.md), [mp5_CONCEPTS.md](../course/mp5_CONCEPTS.md), `reference/course/mini_project_5/src/step1–4*.py` (CEL / WYNIK / WYMAGANIA), `serve.py`, `run_agent_mcp.py`, `run_assistant_eval.py`, `reference/course/mini_project_5/tests/` (w tym `toy_servers/`), `reference/course/helpers/{mcp_runtime,assistant,assistant_eval}.py`, rozmowy `data/eval/mini_project_5_conversations.yaml` (5 rozmów, 12 tur, plus nakładka `mp3_overlays` dla D7) i 8 dialogów MP3 (13 tur): razem **25 tur**.

**Co już jest (nie robimy drugi raz):** agent w węźle `answer_documents` (`workflow.answerer: agent`), prompt `assistant_understand_system` w aplikacji (`workflow.understand_prompt`), koperta `agent_trace` v1 w `record`, pola `transport` i `invocation_id` w `TraceEvent`, `TOOL_SPECS` bez LangChaina (gotowe do rejestracji w FastMCP), kontener `mcp-server` z `/health` i bez narzędzi (F0), `services.mcp_url`, sprawdzenie `mcp` w `/health` api, sekcja `mcp` (PINNED: 60 / 120 / 10 s).

**Czego MP5 wymaga jeszcze od promptu `assistant_understand_system`:** tylko pomiaru. Tekst jest PINNED i w aplikacji od F4; kurs wymaga, żeby asystent używał go zamiast `understand_system` bez modyfikowania konfiguracji (u nas: wybór w `workflow.understand_prompt`, E3 dalej na `understand_system`) i żeby E5 zmierzyło kierowanie na 25 turach. Ponowne przesłanie („Prześlij to.”, „Spróbuj jeszcze raz…”) to `update` w C2 i C3; to sprawdza E5 na żywo.

**F5 jest gotowe, gdy:**
1. `kovalo eval e5` (bez `--live`, zero wywołań LLM-a, serwer MCP w pamięci i przez stdio; stdio z `--search memory` liczy embeddingi korpusu lokalnym fastembedem, więc wymaga modelu w cache, P7): zgodność MCP z wywołaniem bezpośrednim **20/20** (17 wywołań macierzy kursu + 3 nasze dla `check_termination_condition`), odtworzenie 13 rozmów z idealnym `understand` przez MCP **100% w każdym sprawdzeniu** (25 tur, `understand` wywołany 25 razy, agent 4 razy, 0 nieudanych wywołań MCP); raport `reports/mp5/<data>-e5.md` z kolumną kursu.
2. `kovalo eval e5 --live` (`gemini-3.5-flash-lite`, agent przez MCP): cel z [06-evaluation.md](../06-evaluation.md): ścieżka ≥ 24/25, pozostałe sprawdzenia ≥ kurs − 1, wywołania MCP bez błędów; powtórka `--live --cache-only` to 0 wywołań i działa bez `GOOGLE_API_KEY`.
3. `docker compose up -d --build` (`make up`): w przeglądarce (http://localhost:8000) rozmowa C1 przechodzi: kara za lipiec przez agenta z krokami „przez MCP”, wniosek 14% z pauzą „Dyrektor handlowy”, OTIF Aqua Kryształ, ponowne przesłanie bez nowej pauzy. `docker compose logs mcp-server` pokazuje wywołania narzędzi z `invocation_id` z trace.
4. Serwer `kovalo` w `.mcp.json` działa w Claude Code (`claude mcp list`: połączony; pytanie o OTIF Mlecznej Doliny w lipcu daje 94,6% z `get_supplier_otif`), a MCP Inspector widzi 7 narzędzi z `outputSchema` i `readOnlyHint`, szablon zasobu `kovalo://documents/{doc_id}`, zasób `kovalo://policy/course-v1` i prompt `supplier_review` (stdio i HTTP; P4).
5. `uv run pytest` (unit + architektura) zielone w CI; `-m integration` (MCP przez HTTP w compose, agent w grafie z narzędziami MCP na `PostgresSaver`) zielone; `-m live tests/live/test_e5_live.py` to najwyżej 6 wywołań Gemini.

### 2.2 Gdzie co biegnie

- Testy jednostkowe, `eval e5` bez `--live`, `eval e5 --live --cache-only`: bez LLM-a i bez klucza; bez sieci, o ile model fastembed z configu jest już w lokalnym cache (stdio z `--search memory` liczy embeddingi korpusu prawdziwym modelem; testy jednostkowe w transporcie `memory` z `override_embeddings` go nie potrzebują, P7); serwer MCP w pamięci (`in_memory_connection`) albo podproces stdio z `--search memory`; embeddingi przez `override_embeddings` w testach.
- `eval e5 --live` lokalnie: domyślnie stdio (podproces `kovalo-mcp --search memory`, jak w kursie każdy klient uruchamia własny serwer); w compose `--transport http` do `mcp-server` z `pgvector`.
- `api` w compose: agent z narzędziami przez MCP (`tools.source: mcp`, `tools.mcp_transport: http`, `services.mcp_url`); jedno długożyjące połączenie na proces (U3).
- `mcp-server` w compose: `pgvector` (`kovalo_ctx`), `/app/data/company` i `/app/data/corpus` tylko do odczytu, bez klucza LLM-a.
- Claude Code / Claude Desktop / Inspector: stdio, `uv run kovalo-mcp --search memory` (U6); alternatywnie HTTP `http://localhost:8765/mcp` przy działającym compose.

## 5. Budżet wywołań LLM-a (darmowy tier)

Model główny `gemini-3.5-flash-lite` (wysoki dzienny limit; w F4 około 47 wywołań jednego dnia bez 429), fallback `gemini-3.6-flash` (około 20 zapytań dziennie). ### 6.3 Pochodzenie wywołania z artefaktu

`agents/trace._record_result`: jeśli `message.artifact` jest słownikiem z `transport`, to `event.transport = artifact["transport"]`, `event.invocation_id = artifact.get("invocation_id")`; wynik z treści jak w F4. Koperta kursu `{"__mcp__": ..., "record": ...}` w treści nadal jest rozpoznawana (porty testów kursu z narzędziami zwracającymi kopertę). Artefakt nie trafia do modelu ani do `result`. Zdarzenie składowe (`get_supplier_otif` pod `check_termination_condition`) dziedziczy po rodzicu `transport` i `invocation_id` (ten sam odczyt na serwerze; P8).

**Artefakt poza kluczem cache (P1).** `dumps(messages)` w kluczu cache serializuje `ToolMessage.artifact`, więc losowy `invocation_id` zmieniałby klucz od drugiej tury agenta. `StableUsageMiddleware.wrap_model_call` (najbardziej wewnętrzne, dodawane zawsze przez `build_agent`) wysyła do modelu kopie wiadomości z `artifact=None` (`request.override(messages=[m.model_copy(update={"artifact": None}) if isinstance(m, ToolMessage) and m.artifact is not None else m for m in request.messages])`); stan agenta (i trace, który czyta artefakt z kanału `messages` w `run_question`) zostaje bez zmian. Narzędzia bezpośrednie mają `artifact=None`, więc klucze F2–F4 się nie zmieniają. Test: `tests/unit/agents/test_agent.py::test_cache_key_does_not_depend_on_the_tool_artifact`.

### 7.2 Narzędzia (`registry.register_tools`)

```python
def register_tools(server: FastMCP, ctx: ToolContext, variant: ToolsVariant) -> list[str]:
    """Dla każdej spec z tool_specs(variant): fn = spec.make(ctx); rejestruje asynchroniczną nakładkę, która
    wywołuje fn w wątku (anyio.to_thread.run_sync), z tą samą nazwą, docstringiem i sygnaturą
    (__signature__ = inspect.signature(fn, eval_str=True), także adnotacja wyniku = spec.record):
    server.tool(name=spec.name, description=(fn.__doc__ or "").strip(),
    annotations=ToolAnnotations(readOnlyHint=True, idempotentHint=True, openWorldHint=False),
    structured_output=True)(wrapper). Zwraca zarejestrowane nazwy."""
```

- Opis podajemy jawnie (`description=`) tym samym wyrażeniem co `tools/langchain.py` (`(fn.__doc__ or "").strip()`): FastMCP bez tego bierze surowy `__doc__`, a opis musi być równy opisowi narzędzia bezpośredniego, bo od tego zależą trafienia w cache F4 (P3).
- Nakładka jest asynchroniczna, bo FastMCP 1.30 woła funkcję synchroniczną wprost w pętli zdarzeń (zablokowałaby serwer HTTP przy wyszukiwaniu); logika zostaje w `spec.make(ctx)`.
- Każde wywołanie: log `INFO` na stderr z narzędziem, czasem i statusem rekordu (bez argumentów tekstowych dłuższych niż 200 znaków). Identyfikator wywołania nadaje klient; serwer loguje `request_id` JSON-RPC.
- Wyjątek w narzędziu (np. `RuntimeError("indeks dokumentów niedostępny…")`, zły typ argumentu) → FastMCP odsyła `isError: true` (u klienta warstwa `tool`). Zwykłe wyniki dziedzinowe (`no_data`, `not_applicable`, …) to `structuredContent` bez błędu.
- Wariant `course` daje dokładnie 6 narzędzi kursu (porty testów kroku 1), `ours` 7 (aplikacja, Claude Code; U5).
